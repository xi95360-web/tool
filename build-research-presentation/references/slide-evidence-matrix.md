## B. Claim-Level Ledger

证据状态只允许：`PUBLISHED / USER_DATA / PROPOSED / INFERENCE / EVIDENCE_GAP`。

| Claim ID | Slide # | Scientific claim | Status | Source role | Citation + persistent ID | Study type | Exact locator | Source statement/data used | Support: direct/partial/context/conflict | Limitation | Access/read level | Metadata verified? | Claim verified? |

If one claim uses several sources, use several ledger rows with the same Claim ID. If one source supports several claims, use separate rows so each relationship remains auditable.

## Evidence Object Checklist

每个内容页至少包含一种：

- 原始数据图、谱图、显微图或统计图；
- 经忠实简化的论文 figure/panel；
- 实验设计、机制、因果图或分析流程；
- 定量比较表或有来源的数据；
- proposal 的可证伪预测、决策树、功效/样本量依据、里程碑或风险—替代方案；
- 对证据缺口的明确呈现。

“装饰性图片 + 概括句”不算证据对象。

## Slide Contract

发布前逐页确认：

- [ ] 标题是结论或问题，不是泛泛的章节名
- [ ] 视觉对象与标题直接相关
- [ ] 关键数据、对照和结论可在数秒内识别
- [ ] 引用紧邻内容并可追溯到页/图/表
- [ ] Claim ID 能在台账中找到，证据状态使用受控词汇
- [ ] 解释没有超出证据边界
- [ ] 有一句清楚的 take-home
- [ ] 下一页过渡具有逻辑关系
